# Interface: state

Everything the app knows, for whoever is driving it.

> **This document is checked.** `make ci` regenerates the fixture below from
> the live code and fails if it differs from what is committed. If this file
> and the code disagree, the build stops.

- **Produced by:** `writeState()` in `src/main.cpp`, written with `--state file.json`
- **Consumed by:** the `State` struct in `tools/od/app.go`
- **Fixture:** [`testdata/interfaces/state.json`](../../testdata/interfaces/state.json)
- **Written:** every 0.2 s while running, and once on exit

This is the one boundary between the C++ and the Go, and nothing but this
check couples them. The fixture records the **shape** rather than a captured
instance, because fps, renderer and frame counts differ per machine and per
run. It is generated by reflecting over the Go `State` struct, so adding a
field there updates the fixture and forces this document to be revisited.

**Every new feature must remain observable here.** An agent that cannot read
the result cannot verify its own work, and every live check in `tools/od` is
written against these fields. Notable ones earned the hard way:

- `planet.beacon_x/y` and `progress.sigil_x/y` — where the app actually drew
  them, so a driving script never reimplements the layout maths.
- `planet.view_x/y` and `beacon_world_x/y` — enough to navigate to the target
  the way a player does.
- `planet.skits_showing` / `skits_total` — how much of a world the current mix
  is bringing out.
- `rendered_frames` — strictly increasing while the mixer runs; every check
  uses it to prove audio never stalled.
